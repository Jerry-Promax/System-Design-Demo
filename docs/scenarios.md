# 后端系统设计场景索引

这不是一份“面试题答案大全”，而是一张可落地的实验清单。

筛选标准：

- 高频：常见于后端系统设计、场景设计或工程实践面试。
- 可拆解：能抽象出一个明确的核心机制。
- 可观察：用少量接口、日志或测试就能看到行为差异。
- 有取舍：简化实现与生产实现之间能讲清楚差距。

## 分层方式

每道题按四个层次整理：

| 层次 | 要回答的问题 |
| --- | --- |
| 业务目标 | 用户或系统最终需要什么结果？ |
| 核心机制 | 哪个算法、数据结构或协议是解题关键？ |
| 最小 Demo | 去掉哪些外围能力后，仍能证明核心机制成立？ |
| 生产扩展 | 多机、持久化、容灾、观测、安全和成本如何补齐？ |

## 优先级定义

- **P0**：高频且适合做最小 Demo，构成首批内容。
- **P1**：高频但需要额外基础设施或较完整业务链路。
- **P2**：适合作为进阶专题，通常在 P0/P1 中有基础后再做。

状态：

- `TODO`：只有题目和边界。
- `WIP`：正在实现。
- `DONE`：已有可运行 Demo、测试和说明。

## 推荐实施顺序

第一批先做最容易形成统一模板、又能覆盖不同问题类型的场景：

1. `T01` 接口限流：算法 + HTTP 行为。
2. `T04` 幂等下单：状态 + 唯一约束。
3. `D01` 缓存一致性：双写 + 失效 + 补偿。
4. `D03` 分布式锁：竞态 + 租约。
5. `M01` 订单超时：延迟任务 + 状态竞态。
6. `E02` 防止超卖：并发 + 原子扣减。
7. `C01` 短链接：发号 + 编码 + 跳转缓存。
8. `O01` 熔断降级：状态机 + 故障注入。

每一批完成后回看一次 Demo 规范。如果新案例需要普遍修改模板，应优先调整规范，而不是复制出八套不同结构。
